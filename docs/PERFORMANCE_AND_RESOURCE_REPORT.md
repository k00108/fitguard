## 同输入、同边界 PS/PL 基准

`software/pynq/FitGuard_Unified_Test/fitguard_cnn_ps_pl_benchmark.py` 使用同一批 18 个归一化金样，在同一块 PYNQ-Z2 上比较相同计算边界：六层 Conv1D、ReLU、池化与 GAP。PS 侧为 NumPy 实现，PL 侧为最终 bit/hwh 与 AXI DMA；脚本同时核对两侧输出误差，并报告均值、P50、P95和加速比。该工具是独立验收脚本，不改动模型、位流或实时程序。

本包目前只有最终 PL 实测，没有合格的同板 PS 结果。因此 PS 参考时间和 PS/PL 加速比暂不报告，避免把开发机 NumPy 时间与板端 PL 时间混用。评审前应在 PYNQ-Z2 上运行脚本并保留生成的 `fitguard_cnn_ps_pl_benchmark.json`。

## 实时链路证据

本包保留两次相互补充的真实板端记录，不能把两次实验的字段拼成一条虚构记录：

1. `verification/live/live_predictions_gateway_long_run.json`（`cnn_v6_run_0011`）用于长时间运行、三类输出和无线链路统计：
   - 连续运行 `817.591307483 s`，最终手动停止；
   - 737 次分类记录，其中 736 次形成最终标签；
   - 最终标签包含 `Stable` 422 次、`Mild Abnormality` 225 次、`Marked Abnormality` 89 次；
   - 40400 个 IMU 样本，网关接收率 `0.9988132911392406`（约 99.881%）；
   - CRC 错误 1 次、丢样 48 个、乱序 0、队列丢弃 0。
2. `verification/live/live_predictions_gateway_cnn_pl.json`（`cnn_v6_run_0021`）用于证明实时入口确实启用硬件后端：
   - 实际后端 `pl_cnn_conv1d`，`pl_acceleration_active=true`；
   - PL 调用 775 次；
   - 连续运行约 686.98 秒，记录 773 次预测，最终手动停止。
     - 完整模型推理（包括 PS 侧后处理）均值约 `78.95 ms`、P95 约 `85.39 ms`。
     - 相邻分类时间戳间隔 P50 约 `336 ms`、P95 约 `469 ms`；该指标是分类更新间隔，不等同于传感器到显示的端到端延迟。

因此，报告 3.3.5 中的 817.6 秒、737 次分类、40400 个 IMU 样本、99.881% 接收率、1 次 CRC 和 48 个丢样均可直接追溯到第一份原始记录；PL 加速结论则由第二份记录独立证明。运行期的少量链路异常也说明 `DATA_INSUFFICIENT` / `LINK_FAULT` 与自动恢复机制具有实际工程必要性。

## 基线说明

随机森林优化版完整保留在 `models/random_forest_baseline/`。它具有推理轻量、特征可解释和小数据友好的优点；CNN 主模型直接利用时间序列局部模式，能够学习 IMU 与视觉随时间变化的组合关系，更适合当前主线。两者应作为主模型/工程基线关系呈现，而非删除旧模型。
