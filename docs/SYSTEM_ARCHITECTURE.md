# 系统架构与算法边界

## 数据流

```text
MPU6050 → ESP32 节点 → 无线链路 → ESP32 USB 网关 → PYNQ PS
摄像头 → PS 采集 → PL 视觉掩膜 → PS 人物目标跟踪
                          ↓
       IMU 64×7 + 视觉 64×3 时间窗
                          ↓
           PL：双分支六层 Conv1D + Pool + GAP
                          ↓
           PS：Dense/范围特征/融合/Softmax
                          ↓
       转身保护 + 状态防抖 + 链路状态 + 事件记录
                          ↓
      Stable / Mild Abnormality / Marked Abnormality
```

## 双模态意义

IMU 对腰部的动态加速度、角速度和变化速度敏感；视觉提供人物是否在场、目标运动速度、位置变化及跟踪可靠性。视觉不是简单的“亮区最大目标”，而是以变化区域、历史目标和质量评分维护人物目标。两者共同降低单一传感器的歧义：例如转身可引起角速度峰值，但视觉轨迹与转身上下文可避免把它直接误判成重度异常。

## PL/PS 分工

- PL：计算规则固定、并行度高、占主要乘加量的 Conv1D 特征提取，以及既有视觉掩膜算子。
- PS：设备采集、动态目标维护、数据质量判定、输入规范化、范围特征、Dense 融合、概率平滑、状态机、日志和界面。

这种边界保留了工程灵活性，同时让比赛可明确展示 FPGA 的真实加速对象。后端状态必须显示 `pl_cnn_conv1d` 才代表本次运行使用 PL。

## 状态层级

- `WARMING UP`：时间窗尚未填满，三类概率没有足够依据。
- `Stable`：正常稳定运动。
- `Mild Abnormality`：轻度异常，采用连续证据确认以抑制瞬时跳动。
- `Marked Abnormality`：重度异常，高置信度时快速进入，退出更审慎。
- `DATA_INSUFFICIENT`：人物跟踪等输入暂时不可靠，恢复后重新进入正常判定。
- `LINK_FAULT`：IMU 断流或链路异常；恢复数据后应自动解除。

## 设计原则

1. 不用单次位移长短直接区分轻度/重度。
2. 转身作为明确上下文保留，而不是简单删除角速度峰值。
3. 三类模型概率与显示状态分层：模型负责判别，状态机负责可靠呈现。
4. 故障状态不能伪装成三类运动状态。
5. 当前工程保留 NumPy 回退，但对外宣称 PL 加速必须提供后端证据。
